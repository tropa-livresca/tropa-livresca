# Documentação do Modelo de Dados (Supabase/PostgreSQL)

Este documento contém as diretrizes e instruções técnicas sobre o mapeamento estrutural das tabelas do banco de dados do projeto. Ele serve como documentação conceitual e guia de implantação para a arquitetura de persistência.

---

## Instruções para Execução e Implantação

Se você precisar recriar estas tabelas em um banco de dados limpo ou em um novo ambiente do Supabase, siga rigorosamente as diretrizes abaixo:

1. **Geração Automática de IDs (Identity):**
   - As sequências numéricas utilizam a cláusula nativa e padronizada `GENERATED BY DEFAULT AS IDENTITY`, eliminando dependências manuais de objetos sequenciais externos.
   - A tabela `users_profile` adota o tipo `uuid` integrado ao ecossistema do Supabase Auth para controle centralizado de chaves primárias.

2. **Chaves Estrangeiras Pendentes:**
   - Este documento foca estritamente na estrutura estrutural de criação das tabelas. Os comandos de amarração de chaves estrangeiras (`ALTER TABLE ... ADD CONSTRAINT`) devem ser executados apenas **após** a criação bem-sucedida de todas as entidades listadas na arquitetura.

3. **Esquema de Destino:**
   - Todas as entidades estão mapeadas explicitamente para o esquema `public`.

# Estrutura do Banco de Dados

## `users_profile`

```sql
CREATE TABLE public.users_profile (
    id uuid NOT NULL,
    nome text NOT NULL,
    telefone character varying NOT NULL,
    imagem text,
    descricao text,
    redes_sociais jsonb,
    is_admin boolean NOT NULL,
    senha_adm text,
    primeiro_acesso boolean NOT NULL,
    email text,
    is_master boolean,
    dados_bancarios jsonb,
    CONSTRAINT users_profile_pkey PRIMARY KEY (id)
);
```

## Contratos de Dados Confirmados

- `livros.capa` é `jsonb`; o código persiste um objeto com os paths `frente`, `verso` e `orelhas`. URLs assinadas são apenas representação de resposta e não são persistidas.
- `livros.palavras_chave` é `text`, não array nem `jsonb`. A API de autopublicação recebe a lista do formulário e o backend a serializa como texto separado por `; ` antes de gravar; a leitura do frontend converte esse texto em lista para edição.
- `revisoes.fk_livro_id` é a chave para `livros.id`. O schema não tem `revisoes.ativo`; o ciclo de vida da revisão é representado por `completado` e pelo estado do livro.
- `revisoes.arquivo` é `text NOT NULL`; criar revisão exige um manuscrito PDF. A ausência de arquivo não é permitida pelo service.
- `livros.publico_alvo` não está definido neste schema e não é uma coluna persistida pelo backend atual. Nenhuma coluna foi adicionada à DDL ou ao DER. Persistir esse dado no futuro exige uma migração aprovada e documentada antes de alterar o código.

Essas decisões descrevem o schema documentado neste repositório. Não executam nem propõem uma alteração automática no banco real.

## Relacionamentos e Restrições (Chaves Estrangeiras)

As diretivas abaixo realizam as amarrações lógicas entre as entidades do ecossistema. Certifique-se de executar este bloco **apenas após** a criação de todas as tabelas listadas anteriormente.

```sql
-- Tabela: movimentacoes_financeiras
ALTER TABLE public.movimentacoes_financeiras
    ADD CONSTRAINT fk_movimentacoes_venda
    FOREIGN KEY (fk_vendas_id) REFERENCES public.vendas (id);

ALTER TABLE public.movimentacoes_financeiras
    ADD CONSTRAINT fk_movimentacoes_usuario
    FOREIGN KEY (fk_user_profile_id) REFERENCES public.users_profile (id);

-- Tabela: comentarios
ALTER TABLE public.comentarios
    ADD CONSTRAINT comentarios_fk_user_profile_id_fkey
    FOREIGN KEY (fk_user_profile_id) REFERENCES public.users_profile (id);

-- Tabela: itens_venda
ALTER TABLE public.itens_venda
    ADD CONSTRAINT itens_venda_fk_livros_itens_id_fkey
    FOREIGN KEY (fk_livros_itens_id) REFERENCES public.livros (id);

ALTER TABLE public.itens_venda
    ADD CONSTRAINT itens_venda_fk_vendas_id_fkey
    FOREIGN KEY (fk_vendas_id) REFERENCES public.vendas (id);

-- Tabela: vendas
ALTER TABLE public.vendas
    ADD CONSTRAINT vendas_fk_user_profile_id_fkey
    FOREIGN KEY (fk_user_profile_id) REFERENCES public.users_profile (id);

-- Tabela: revisoes
ALTER TABLE public.revisoes
    ADD CONSTRAINT revisoes_fk_livro_id_fkey
    FOREIGN KEY (fk_livro_id) REFERENCES public.livros (id);

ALTER TABLE public.revisoes
    ADD CONSTRAINT revisoes_fk_user_profile_id_fkey
    FOREIGN KEY (fk_user_profile_id) REFERENCES public.users_profile (id);

-- Tabela: enderecos
ALTER TABLE public.enderecos
    ADD CONSTRAINT enderecos_fk_user_profile_id_fkey
    FOREIGN KEY (fk_user_profile_id) REFERENCES public.users_profile (id);

-- Tabela: livros
ALTER TABLE public.livros
    ADD CONSTRAINT livros_fk_user_profile_id_fkey
    FOREIGN KEY (fk_user_profile_id) REFERENCES public.users_profile (id);

-- Tabela: avaliacoes
ALTER TABLE public.avaliacoes
    ADD CONSTRAINT avaliacoes_fk_livros_id_fkey
    FOREIGN KEY (fk_livros_id) REFERENCES public.livros (id);

ALTER TABLE public.avaliacoes
    ADD CONSTRAINT avaliacoes_fk_users_profile_id_fkey
    FOREIGN KEY (fk_users_profile_id) REFERENCES public.users_profile (id);
```
