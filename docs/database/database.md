# Documentação do Modelo de Dados (Supabase/PostgreSQL)

Este documento contém as diretrizes e instruções técnicas sobre o mapeamento estrutural das tabelas do banco de dados do projeto Tropa Livresca. Ele serve como documentação conceitual e guia de implantação para a arquitetura de persistência.

---

## Instruções para Execução e Implantação

Se for necessário recriar estas tabelas em um banco de dados limpo ou em um novo ambiente do Supabase, siga as diretrizes abaixo:

1. **Geração automática de IDs (`IDENTITY`):**
   - As tabelas que utilizam identificadores numéricos adotam a cláusula `GENERATED BY DEFAULT AS IDENTITY`, permitindo a geração automática de valores para suas chaves primárias.
   - A tabela `users_profile` utiliza o tipo `uuid` para seu identificador, compatível com o ecossistema de autenticação do Supabase.

2. **Chaves estrangeiras:**
   - As tabelas são criadas inicialmente com suas chaves primárias.
   - As restrições de chave estrangeira são adicionadas posteriormente, utilizando `ALTER TABLE ... ADD CONSTRAINT`, após a criação de todas as tabelas envolvidas.
   - Os relacionamentos apresentados neste documento são inferidos pelas colunas `fk_*` fornecidas. Antes da implantação, deve-se verificar se as restrições já existem no banco para evitar duplicações.

3. **Esquema de destino:**
   - Todas as tabelas estão definidas explicitamente no esquema `public`.

4. **Preservação da estrutura:**
   - Os tipos de dados, as restrições `NOT NULL` e as chaves primárias abaixo reproduzem a DDL fornecida.
   - Não são adicionadas colunas, valores padrão ou restrições adicionais às definições originais.

# Estrutura do Banco de Dados

## `users_profile`

Armazena os perfis dos usuários, informações administrativas, dados de contato, redes sociais e dados bancários.

```sql
CREATE TABLE public.users_profile (
    id uuid NOT NULL,
    nome text NOT NULL,
    telefone character varying NOT NULL,
    imagem text,
    descricao text,
    redes_sociais jsonb,
    is_admin boolean NOT NULL,
    senha_adm text,
    primeiro_acesso boolean NOT NULL,
    email text,
    is_master boolean,
    dados_bancarios jsonb,
    CONSTRAINT users_profile_pkey PRIMARY KEY (id)
);
```

**Chave primária:** `id`.

**Relacionamentos:** referenciada pelas tabelas `livros`, `avaliacoes`, `vendas`, `movimentacoes_financeiras`, `enderecos` e `revisoes`.

**Observação:** a coluna `id` utiliza UUID. A DDL fornecida não define um valor padrão para essa coluna nem declara explicitamente uma chave estrangeira para `auth.users`.

## `itens_venda`

Armazena os itens associados às vendas, incluindo quantidade, subtotal, preço unitário e indicação de produto físico.

```sql
CREATE TABLE public.itens_venda (
    id bigint GENERATED BY DEFAULT AS IDENTITY NOT NULL,
    qtd bigint NOT NULL,
    subtotal numeric NOT NULL,
    fk_livros_itens_id bigint NOT NULL,
    fk_vendas_id bigint NOT NULL,
    fisico boolean NOT NULL,
    preco_unitario numeric NOT NULL,
    CONSTRAINT itens_venda_pkey PRIMARY KEY (id)
);
```

**Chave primária:** `id`.

**Relacionamentos previstos:**

- `fk_livros_itens_id` → `livros.id`.
- `fk_vendas_id` → `vendas.id`.

**Observação:** `subtotal` e `preco_unitario` utilizam o tipo `numeric`, apropriado para valores monetários quando acompanhados de precisão e escala adequadas à aplicação.

## `livros`

Armazena as informações bibliográficas, editoriais e comerciais dos livros publicados ou submetidos pelos usuários.

```sql
CREATE TABLE public.livros (
    id bigint GENERATED BY DEFAULT AS IDENTITY NOT NULL,
    direitos_de_publicacao boolean NOT NULL,
    imagens_explicitas boolean NOT NULL,
    numero_edicao smallint,
    data_de_publicacao date NOT NULL,
    preco_digital numeric NOT NULL,
    preco_fisico numeric NOT NULL,
    titulo text NOT NULL,
    subtitulo text NOT NULL,
    descricao text NOT NULL,
    autor_nome text NOT NULL,
    autor_sobrenome text NOT NULL,
    fk_user_profile_id uuid NOT NULL,
    ativo boolean NOT NULL,
    estado character varying NOT NULL,
    idioma text NOT NULL,
    manuscrito text,
    colaboradores jsonb,
    capa jsonb,
    categoria text,
    ISBN text,
    numero_paginas smallint,
    CONSTRAINT livros_pkey PRIMARY KEY (id)
);
```

**Chave primária:** `id`.

**Relacionamentos previstos:**

- `fk_user_profile_id` → `users_profile.id`.
- Referenciada por `itens_venda`, `avaliacoes` e `revisoes`.

**Observações:**

- `capa` utiliza `jsonb`, permitindo armazenar a estrutura de dados das capas.
- `colaboradores` também utiliza `jsonb`.
- `estado` representa o estado do livro no fluxo de publicação, conforme as regras implementadas pela aplicação.
- `numero_edicao` e `numero_paginas` utilizam `smallint`.

## `avaliacoes`

Armazena as avaliações dos livros, identificando o livro avaliado, o usuário responsável e a quantidade de estrelas atribuída.

```sql
CREATE TABLE public.avaliacoes (
    id bigint GENERATED BY DEFAULT AS IDENTITY NOT NULL,
    data_criacao timestamp with time zone NOT NULL,
    fk_livros_id bigint,
    fk_users_profile_id uuid,
    qtd_estrelas smallint,
    CONSTRAINT avaliacoes_pkey PRIMARY KEY (id)
);
```

**Chave primária:** `id`.

**Relacionamentos previstos:**

- `fk_livros_id` → `livros.id`.
- `fk_users_profile_id` → `users_profile.id`.

**Observação:** as duas colunas de relacionamento e a coluna `qtd_estrelas` permitem valores nulos na DDL fornecida. Não foi declarada uma restrição de intervalo para a quantidade de estrelas.

## `vendas`

Armazena os dados das vendas realizadas, incluindo data, total, método de pagamento, estado do pagamento, estado da entrega e endereço de entrega.

```sql
CREATE TABLE public.vendas (
    id bigint GENERATED BY DEFAULT AS IDENTITY NOT NULL,
    data timestamp with time zone NOT NULL,
    total numeric NOT NULL,
    metodo_pagamento bigint NOT NULL,
    status_pagamento text NOT NULL,
    fk_user_profile_id uuid NOT NULL,
    endereco_entrega jsonb,
    status_entrega text NOT NULL,
    CONSTRAINT vendas_pkey PRIMARY KEY (id)
);
```

**Chave primária:** `id`.

**Relacionamento previsto:**

- `fk_user_profile_id` → `users_profile.id`.
- Referenciada por `itens_venda` e `movimentacoes_financeiras`.

**Observações:**

- `endereco_entrega` utiliza `jsonb`, permitindo armazenar uma representação do endereço associado à compra.
- `metodo_pagamento` é declarado como `bigint NOT NULL`, mas a DDL fornecida não identifica a tabela de destino desse campo. Por isso, nenhuma chave estrangeira foi definida para ele.

## `movimentacoes_financeiras`

Registra as movimentações financeiras relacionadas aos usuários e às vendas, incluindo tipo, valor, descrição e estado da movimentação.

```sql
CREATE TABLE public.movimentacoes_financeiras (
    id bigint GENERATED BY DEFAULT AS IDENTITY NOT NULL,
    data timestamp with time zone NOT NULL,
    fk_user_profile_id uuid,
    fk_vendas_id bigint,
    tipo text NOT NULL,
    valor numeric NOT NULL,
    descricao text NOT NULL,
    status text NOT NULL,
    CONSTRAINT movimentacoes_financeiras_pkey PRIMARY KEY (id)
);
```

**Chave primária:** `id`.

**Relacionamentos previstos:**

- `fk_user_profile_id` → `users_profile.id`.
- `fk_vendas_id` → `vendas.id`.

**Observação:** ambas as colunas de relacionamento aceitam valores nulos, conforme a definição original.

## `enderecos`

Armazena os endereços associados aos perfis dos usuários, incluindo informações de localização, identificação do endereço e indicação de endereço principal.

```sql
CREATE TABLE public.enderecos (
    id bigint GENERATED BY DEFAULT AS IDENTITY NOT NULL,
    estado character varying NOT NULL,
    bairro text NOT NULL,
    rua text NOT NULL,
    num integer NOT NULL,
    cep character varying NOT NULL,
    fk_user_profile_id uuid NOT NULL,
    cidade text NOT NULL,
    complemento text,
    pais text,
    ativo boolean,
    principal boolean,
    CONSTRAINT enderecos_pkey PRIMARY KEY (id)
);
```

**Chave primária:** `id`.

**Relacionamento previsto:**

- `fk_user_profile_id` → `users_profile.id`.

**Observação:** as colunas `ativo` e `principal` permitem valores nulos na DDL original. A função `gerenciar_endereco_principal_automatico` pode atuar nessa tabela caso esteja associada aos gatilhos correspondentes.

## `revisoes`

Armazena os apontamentos de revisão associados a um livro e ao usuário responsável, incluindo data de criação, nome e estado de conclusão.

```sql
CREATE TABLE public.revisoes (
    id bigint GENERATED BY DEFAULT AS IDENTITY NOT NULL,
    data_criacao timestamp with time zone NOT NULL,
    apontamento text,
    fk_user_profile_id uuid NOT NULL,
    fk_livro_id bigint NOT NULL,
    nome text,
    completado boolean NOT NULL,
    CONSTRAINT revisoes_pkey PRIMARY KEY (id)
);
```

**Chave primária:** `id`.

**Relacionamentos previstos:**

- `fk_user_profile_id` → `users_profile.id`.
- `fk_livro_id` → `livros.id`.

**Observação:** a estrutura fornecida não contém uma coluna `arquivo` nem uma coluna `ativo`. A documentação preserva a DDL mais recente, sem acrescentar campos de versões anteriores.

# Contratos de Dados Confirmados

- `users_profile.id` é `uuid` e constitui a chave primária do perfil.
- As demais tabelas utilizam identificadores `bigint` com geração automática por `IDENTITY`.
- `livros.capa` e `livros.colaboradores` são campos `jsonb`.
- `vendas.endereco_entrega` é `jsonb`.
- `users_profile.redes_sociais` e `users_profile.dados_bancarios` são campos `jsonb`.
- `itens_venda.fk_livros_itens_id` referencia logicamente um livro, enquanto `itens_venda.fk_vendas_id` referencia uma venda.
- `revisoes.fk_livro_id` identifica o livro relacionado à revisão.
- A DDL fornecida não declara explicitamente as chaves estrangeiras. Os relacionamentos descritos acima precisam ser verificados no catálogo do PostgreSQL antes da implantação.

# Relacionamentos e Restrições (Chaves Estrangeiras)

As instruções seguintes adicionam as restrições de integridade referencial. Execute-as **somente após a criação de todas as tabelas** e depois de verificar se as restrições já existem.

```sql
-- Tabela: itens_venda

ALTER TABLE public.itens_venda
    ADD CONSTRAINT itens_venda_fk_livros_itens_id_fkey
    FOREIGN KEY (fk_livros_itens_id)
    REFERENCES public.livros (id);

ALTER TABLE public.itens_venda
    ADD CONSTRAINT itens_venda_fk_vendas_id_fkey
    FOREIGN KEY (fk_vendas_id)
    REFERENCES public.vendas (id);


-- Tabela: livros

ALTER TABLE public.livros
    ADD CONSTRAINT livros_fk_user_profile_id_fkey
    FOREIGN KEY (fk_user_profile_id)
    REFERENCES public.users_profile (id);


-- Tabela: avaliacoes

ALTER TABLE public.avaliacoes
    ADD CONSTRAINT avaliacoes_fk_livros_id_fkey
    FOREIGN KEY (fk_livros_id)
    REFERENCES public.livros (id);

ALTER TABLE public.avaliacoes
    ADD CONSTRAINT avaliacoes_fk_users_profile_id_fkey
    FOREIGN KEY (fk_users_profile_id)
    REFERENCES public.users_profile (id);


-- Tabela: vendas

ALTER TABLE public.vendas
    ADD CONSTRAINT vendas_fk_user_profile_id_fkey
    FOREIGN KEY (fk_user_profile_id)
    REFERENCES public.users_profile (id);


-- Tabela: movimentacoes_financeiras

ALTER TABLE public.movimentacoes_financeiras
    ADD CONSTRAINT fk_movimentacoes_venda
    FOREIGN KEY (fk_vendas_id)
    REFERENCES public.vendas (id);

ALTER TABLE public.movimentacoes_financeiras
    ADD CONSTRAINT fk_movimentacoes_usuario
    FOREIGN KEY (fk_user_profile_id)
    REFERENCES public.users_profile (id);


-- Tabela: enderecos

ALTER TABLE public.enderecos
    ADD CONSTRAINT enderecos_fk_user_profile_id_fkey
    FOREIGN KEY (fk_user_profile_id)
    REFERENCES public.users_profile (id);


-- Tabela: revisoes

ALTER TABLE public.revisoes
    ADD CONSTRAINT revisoes_fk_livro_id_fkey
    FOREIGN KEY (fk_livro_id)
    REFERENCES public.livros (id);

ALTER TABLE public.revisoes
    ADD CONSTRAINT revisoes_fk_user_profile_id_fkey
    FOREIGN KEY (fk_user_profile_id)
    REFERENCES public.users_profile (id);
```
